# 11. ComputeShader — 이건 어떻게 만들었을까?

1~10단계에서는 항상 "그리기(Draw)" 파이프라인만 썼어요. 정점을 넣고, 셰이더로
색을 계산하고, 화면에 삼각형을 그리는 방식이었죠. 이번 단계에서는 D3D12의 또 다른
축인 **컴퓨트 파이프라인**을 처음 써봐요. 그리기 없이, GPU에게 "이 계산만 해줘"라고
시키는 방식이에요. 완성된 화면을 컴퓨트 셰이더로 흐릿하게(블러) 만들어서 그 차이를
눈으로 확인해요.

## 1. 그리기(Draw)와 계산(Compute)은 뭐가 다를까?

지금까지 쓴 그래픽스 파이프라인은 항상 정해진 순서가 있었어요: 정점을 넣으면 →
정점 셰이더 → 래스터화(삼각형을 픽셀로 쪼갬) → 픽셀 셰이더 → 화면. 삼각형을 그리지
않는 작업(예: "이미 그려진 이미지를 흐리게 만들기")에는 이 순서가 전혀 필요 없어요.

컴퓨트 셰이더는 이 순서를 다 걷어내고, "이만큼의 데이터를 병렬로 계산해줘"만 남긴
가장 단순한 형태예요. 정점도, 삼각형도, 래스터화도 없어요. 그냥 GPU 스레드 여러
개가 각자 자기 몫의 픽셀을 계산할 뿐이에요.

## 2. 이번 단계에서 계산할 것: 3x3 박스 블러

원리는 아주 단순해요. 화면의 픽셀 하나마다, **자기 자신과 주변 8개 픽셀(총 9개)의
색을 평균 내서** 그 자리에 다시 써요. 이렇게 하면 픽셀 하나하나의 색이 이웃과 섞여서
전체적으로 부드럽고 흐릿해 보여요.

```hlsl
float4 sum = 0;
for (dy = -1 ~ 1)
  for (dx = -1 ~ 1)
    sum += InputTexture.Load(현재 픽셀 + (dx, dy));
결과 = sum / 9;
```

## 3. 등장인물 소개

| 용어 | 비유 |
|---|---|
| 컴퓨트 셰이더 (`Compute Shader`) | 그리기(래스터화) 없이 GPU에서 그냥 "계산만" 시키는 프로그램. 이번엔 화면 후처리(블러)에 사용 |
| 스레드 그룹 (`numthreads`) | 컴퓨트 셰이더가 한 번에 실행하는 "일꾼 묶음" 크기. 여기선 가로 8명 x 세로 8명 = 64명이 한 그룹 |
| `Dispatch` | "이만큼의 그룹을 통째로 실행해줘"라고 CPU가 GPU에 내리는 명령 (그리기의 `DrawInstanced`에 해당) |
| UAV (`RWTexture2D`) | 컴퓨트 셰이더가 읽기만이 아니라 "쓰기"도 할 수 있는 리소스 뷰. 블러 결과를 여기 저장 |
| SRV (`Texture2D`) | 블러링할 원본 이미지를 "읽기 전용"으로 보는 뷰 |
| 리졸브 → 블러 → 복사 | MSAA 리졸브 결과(원본) → 컴퓨트 셰이더로 3x3 블러 → 그 결과를 백버퍼로 복사하는 순서 |

## 4. 실제로 한 일

1. **블러 후처리용 텍스처 2장 준비** (`InitComputePostProcess`) — 10단계까지는
   MSAA 리졸브 결과를 곧장 백버퍼로 옮겼는데, 이번엔 그 대신 별도의 오프스크린
   텍스처(`m_resolvedColorTarget`)로 리졸브해요. 컴퓨트 셰이더가 이 텍스처를
   읽어서(SRV), 또 다른 텍스처(`m_blurredColorTarget`)에 블러 결과를 써요(UAV).
2. **컴퓨트 전용 루트 시그니처** (`InitComputePostProcess`) — SRV(t0)와 UAV(u0)를
   담은 디스크립터 테이블 하나로 구성해요. 컴퓨트 셰이더는 정점/픽셀 같은 단계
   구분이 없어서, `ShaderVisibility`는 항상 `ALL`이에요.
3. **컴퓨트 PSO 생성** (`InitComputePostProcess`) — 그래픽스 PSO와 달리 정점
   레이아웃도, 래스터라이저 설정도, 렌더 타깃 포맷도 필요 없어요.
   `D3D12_COMPUTE_PIPELINE_STATE_DESC`는 루트 시그니처와 컴퓨트 셰이더 코드,
   딱 두 개만 있으면 돼요.
4. **블러 셰이더 작성** (`BlurCompute.hlsl`) — `[numthreads(8, 8, 1)]`로 한
   그룹이 8x8 = 64개의 스레드를 갖도록 선언하고, 각 스레드가 자기 좌표
   (`SV_DispatchThreadID`) 픽셀 하나를 맡아 3x3 평균을 계산해요.
5. **파이프라인 흐름 변경** (`Render`) — 9~10단계와 똑같이 그림자 → 스카이박스
   + 큐브 + 바닥을 그린 뒤, 리졸브까지는 그대로예요. 그 다음이 새로 추가된
   부분이에요:
   - 리졸브 결과를 곧장 백버퍼로 보내는 대신, 오프스크린 텍스처로 리졸브
   - `SetPipelineState`/`SetComputeRootSignature`/`SetComputeRootDescriptorTable`로
     컴퓨트 파이프라인을 준비하고 `Dispatch`로 블러 실행
   - 블러 결과 텍스처를 `CopyResource`로 그 프레임의 백버퍼에 복사한 뒤 `Present`

## 5. 왜 `Dispatch`에 화면 크기를 그대로 안 쓸까?

화면이 1280x720이고 스레드 그룹이 8x8이면, `1280 / 8 = 160`, `720 / 8 = 90`으로
딱 나누어떨어져서 괜찮지만, 만약 화면 크기가 8의 배수가 아니면 그룹 개수가
소수점이 나와요. 그래서 `(width + 7) / 8`처럼 올림 계산을 해서 그룹을 하나 더
넉넉하게 돌리고, 셰이더 안에서 "내 좌표가 화면 밖이면 그냥 아무것도 안 하고
끝내기"로 초과분을 걸러내요.

## 6. 결과 화면에서 확인할 수 있는 것

10단계와 같은 장면(회전하는 큐브, 그림자, 하늘 배경)이지만, 이번엔 큐브 표면과
바닥의 체크무늬 경계가 전체적으로 부드럽게 번져 보여요. MSAA가 다듬어주는 건
도형의 삐뚤빼뚤한 모서리뿐이었지만, 이번 블러는 이미지 전체에 적용되는
후처리라서 무늬 자체가 뭉개지듯 흐려지는 게 뚜렷하게 보여요.

## 7. 요약 한 줄

> 주변 9개를 평균 낸 흐릿한 이미지로 바꿔치기한" 프로그램.
