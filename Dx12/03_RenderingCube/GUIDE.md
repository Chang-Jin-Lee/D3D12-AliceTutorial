# 03. RenderingCube — 이건 어떻게 만들었을까?

이번엔 평평한 삼각형이 아니라, **회전하는 3D 큐브**를 그려요. 3D를 화면(2D)에
보여주려면 새로운 개념 3가지가 필요해요: **깊이(뎁스) 버퍼**, **인덱스 버퍼**,
**변환 행렬(카메라/움직임 계산)**.

## 1. 3D를 그릴 때 생기는 새로운 문제들

- 큐브는 앞면, 뒷면, 옆면이 겹쳐 보여요. **어느 면이 더 가까운지** 컴퓨터가 알아야
  뒷면이 앞면을 가리는 이상한 그림이 안 나와요. → **뎁스 버퍼**로 해결
- 큐브는 꼭짓점이 8개인데, 각 꼭짓점은 여러 삼각형에서 공유돼요. 매번 좌표를
  새로 적으면 낭비예요. → **인덱스 버퍼**로 해결
- 큐브를 회전시키고, 카메라도 어딘가에 놓고, 그걸 다시 평평한 화면에 눌러 담아야
  해요. → **변환 행렬(월드 * 뷰 * 프로젝션)** 로 해결

## 2. 등장인물 소개

| 용어 | 비유 |
|---|---|
| 뎁스 버퍼 (`Depth Buffer`) | 화면의 각 픽셀마다 "지금까지 그려진 것 중 가장 가까운 거리"를 적어두는 메모장. 새 픽셀을 그릴 때 이 메모보다 멀면 안 그림 |
| 인덱스 버퍼 (`Index Buffer`) | "몇 번, 몇 번, 몇 번 점을 이으면 삼각형 하나" 라는 번호 목록. 점 좌표를 반복해서 안 적어도 됨 |
| 상수 버퍼 (`Constant Buffer`) + 루트 CBV | 매 프레임 바뀌는 값(이번엔 회전 각도가 반영된 행렬 하나)을 GPU에 전달하는 작은 우편함 |
| 월드 행렬 (World) | "큐브를 얼마나 돌릴까?" |
| 뷰 행렬 (View) | "카메라가 어디에 있고 어디를 보고 있을까?" |
| 프로젝션 행렬 (Projection) | "3D 공간을 눌러서 평평한 화면(2D)에 담는 방법" |

이 세 행렬을 순서대로 곱한 걸 보통 **MVP 행렬**이라고 불러요.

## 3. 실제로 한 일

1. **뎁스 버퍼 준비** (`InitDepthBuffer`) — 화면 크기만큼의 "거리 메모장"을 만들고,
   프레임마다 `ClearDepthStencilView`로 초기화해요.
2. **큐브 데이터 만들기** (`InitCubeGeometry`) — 꼭짓점 8개(위치+색깔)와, 삼각형
   12개(=인덱스 36개)를 어떻게 이을지 배열로 적어요.
3. **상수 버퍼 준비** (`InitConstantBuffer`) — 회전 행렬을 담을 자리를 GPU 메모리에
   미리 만들어둬요. 매 프레임 여기에 새 값만 덮어써요.
4. **루트 시그니처에 CBV 추가** (`InitRootSignature`) — "이제 행렬 데이터도 하나 줄
   거야" 라고 계약서를 업데이트해요.
5. **매 프레임 계산** (`Update`) — 실행된 지 몇 초 지났는지 재서, 그 시간만큼 큐브를
   회전시킨 월드 행렬을 만들고, 카메라(뷰)와 화면 비율(프로젝션)까지 곱해서 상수
   버퍼에 써넣어요.
6. **그리기** (`Render`) — 뎁스 버퍼를 함께 초기화하고, `IASetIndexBuffer` +
   `DrawIndexedInstanced`로 인덱스 버퍼를 이용해 그려요.

## 4. 왜 아직 "컬링"은 안 켰을까?

큐브의 뒷면은 화면에 안 보이니까, 사실 GPU가 계산할 필요도 없어요. 이걸 미리
걸러내는 기능이 **백페이스 컬링**이에요. 다만 컬링을 켜려면 꼭짓점을 순서대로
이었을 때 "시계 방향인지 반시계 방향인지"를 정확히 맞춰야 해요. 이번 단계는
그 부분(와인딩 순서)을 아직 안 다뤄서, 일단 컬링을 꺼둔 채로(`D3D12_CULL_MODE_NONE`)
넘어갔어요. 대신 뎁스 버퍼가 있어서 겉보기엔 결과가 똑같이 정상적으로 보여요.

## 5. 요약 한 줄

> "8개 점 + 이어붙이는 규칙(인덱스)으로 큐브를 만들고, 회전값이 담긴 행렬을 매
> 프레임 GPU에 넘겨서 돌아가는 3D 큐브를 그린" 프로그램.

다음 단계(04. TextureMapping)에서는 이 큐브에 무늬(텍스처)를 입히고, 컬링도 켜요.
