# 04. TextureMapping — 이건 어떻게 만들었을까?

3단계까지는 큐브 표면이 그냥 단색(꼭짓점 색이 섞인 색)이었어요. 이번엔 큐브 표면에
**체크무늬 그림(텍스처)**을 입혀요. 마치 상자에 포장지를 씌우는 것과 비슷해요.

## 1. 텍스처를 입히려면 뭐가 필요할까?

포장지를 상자에 씌운다고 생각해보면:
1. **포장지 그림 자체** (텍스처 이미지)
2. **포장지의 어느 부분이 상자의 어느 면에 닿는지** (UV 좌표)
3. **포장지를 어떻게 확대/축소/반복할지 규칙** (샘플러)
4. 그리고 이번엔 **상자 안쪽은 안 보이니까 안 그려도 된다**는 최적화(컬링)도 같이 넣었어요.

## 2. 등장인물 소개

| 용어 | 비유 |
|---|---|
| 텍스처 (`Texture2D`) | 물체 표면에 씌우는 그림(포장지) |
| UV 좌표 | 포장지 위의 좌표. "이 꼭짓점은 포장지의 (0,0) 지점에 닿아있어" 같은 정보 |
| 샘플러 (`Sampler`) | "포장지 색을 가져올 때 부드럽게 섞을지, 반복시킬지" 정하는 규칙 |
| SRV (`Shader Resource View`) | GPU 셰이더가 텍스처를 "읽기 전용"으로 볼 수 있게 만든 이름표 |
| 백페이스 컬링 (`Back-face Culling`) | 상자의 안쪽 면(카메라 반대쪽 면)은 안 보이니 애초에 그리지 않는 것 |
| 와인딩 순서 (`Winding Order`) | 삼각형의 세 꼭짓점을 "시계 방향"으로 도는지 "반시계 방향"으로 도는지의 규칙. 컬링이 이걸 기준으로 앞/뒤를 판단함 |

## 3. 실제로 한 일

1. **체크무늬 그림 직접 만들기** (`InitTexture`) — 이미지 파일을 불러오지 않고,
   코드에서 8x8 흑백 체크무늬를 숫자로 직접 채워요. 그림판 없이 "격자무늬 색칠하기"를
   코드로 한 것과 같아요.
2. **텍스처를 GPU 메모리로 올리기** — 텍스처는 CPU가 아니라 GPU가 빠르게 접근할 수
   있는 특별한 메모리(DEFAULT 힙)에 있어야 해요. 그래서 "일단 CPU가 쓰기 쉬운 임시
   메모리에 그림을 두고 → GPU 명령으로 진짜 텍스처 메모리에 복사"하는 2단계 과정을
   거쳐요 (`CopyTextureRegion`).
3. **큐브에 UV 좌표 추가** (`InitCubeGeometry`) — 이전엔 꼭짓점 8개였는데, 이번엔
   면마다 포장지 좌표가 달라야 해서 꼭짓점을 24개(면당 4개)로 늘렸어요.
4. **꼭짓점 순서(와인딩) 정리** — 컬링을 켜려면 각 면의 꼭짓점이 "바깥에서 봤을 때
   시계 방향"으로 정확히 이어져야 해요. 순서가 틀리면 그 면이 통째로 안 보여요.
5. **루트 시그니처에 SRV + 샘플러 추가** (`InitRootSignature`) — "이제 텍스처 하나랑,
   그걸 읽는 규칙(샘플러)도 같이 줄게" 라고 계약서를 또 업데이트해요.
6. **컬링 켜기** (`InitPipelineState`) — `D3D12_CULL_MODE_BACK`으로 바꿔서, 안 보이는
   뒷면은 그리지 않도록 GPU에게 알려줘요.
7. **픽셀 셰이더에서 색 대신 텍스처 읽기** (`Shaders.hlsl`) — `PSMain`이 더 이상 꼭짓점
   색을 쓰지 않고, `g_texture.Sample(...)`로 포장지 그림에서 색을 가져와요.

## 4. 어떻게 "제대로 됐다"를 확인했을까?

컬링을 켠 상태에서 큐브의 모든 면이 정상적으로 보이는지 확인했어요. 만약 와인딩
순서가 하나라도 틀렸다면, 그 면은 "뒷면"으로 오해받아서 사라져 보였을 거예요.
스크린샷에서 큐브 표면이 전부 체크무늬로 꽉 채워져 있다는 게, 순서가 맞았다는 증거예요.

## 5. 요약 한 줄

> "체크무늬 그림을 코드로 만들어 GPU 텍스처로 올리고, 큐브 각 면에 좌표(UV)를 붙여서
> 입힌 다음, 안 보이는 뒷면은 그리지 않게(컬링) 만든" 프로그램.

여기까지가 그래픽 파이프라인의 기본 뼈대예요. 다음 단계부터는 조명(라이팅) 같은
더 realistic한 효과를 다룰 수 있어요.
